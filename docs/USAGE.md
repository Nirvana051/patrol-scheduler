# 使用说明

巡检调度台的日常操作手册：装好、跑起来、把一次巡检从头做完，以及出问题时看哪里。

- 只想快速看能不能跑：读 [§1 装与启动](#1-装与启动) → [§2 五分钟先在仿真里跑一遍](#2-五分钟先在仿真里跑一遍)。
- 要接真机上线：读 [§3 接真机](#3-接真机)，安全细则在 [OPERATIONS.md](OPERATIONS.md)。
- 逐步验收清单在 [TEST_PLAN.md](TEST_PLAN.md)；设计与问题清单在 [task.md](task.md)；全部文档的导航在 [README.md](README.md)。

---

## 0. 它做什么

在 certaintyX 机器狗云端 API 之上的**本地网页操作台**：

```
你在网页上定义「任务航点」（去哪儿 + 看什么 + 怎么答 + 怎么播报）
        ↓
执行任务：按「起点 → 第一个任务航点 → 下一个…」分段下发给云端
        ↓
每到一个任务航点：抓一张 360° 全景 → 按你圈的角度范围裁切
        → 交给 VLM 用你的 prompt 判「是 / 不是」→ 按答案模版合成语音播报
        ↓
全过程落库：执行、分段、检查（原图/裁切图/回答）、云端与系统事件
```

为什么要分段：机器狗**不能在航点暂停**。一次 `POST /task` 下发一条路径，机器人会一口气走完。所以每个巡检点都要单独下发一段，走到了才有机会停下来拍照判读。

两个必须分清的名词：

| | 含义 | 来自 |
|---|---|---|
| **导航航点** | 地图自带的点，编号 `1`、`2`、`12`…，带坐标和邻接关系 | 机器人的地图（只读） |
| **任务航点** | 你定义的巡检点：落在某个导航航点上 + 检查 prompt + 全景角度范围 + 答案模版 + 参考图 | 本系统 |

## 1. 装与启动

一次性准备（已经装过就跳过）：

```bash
cd /home/leo/agent/scheduler
python3 -m venv --without-pip --system-site-packages .venv
pip3 --python .venv/bin/python install -r requirements.txt
sudo apt-get install -y ffmpeg          # 抓全景要用
```

日常启停（后台运行，日志在 `data/logs/`）：

```bash
./start.sh              # 按 config/.env 启动，并打开浏览器 http://127.0.0.1:8088
./start.sh --mock       # 仿真模式：先起本机 mock 云端网关，不需要任何真机凭据
./start.sh --audio      # 叠加：同时起本机播报服务（听 TTS）
./start.sh --status     # 看进程状态 + 机器人前置检查
./start.sh --stop       # 全部停掉
./start.sh --restart    # 重启（参数可叠加：--restart --mock --audio）
```

`make start` / `make stop` / `make status` 是同样的东西（`make start ARGS="--mock --audio"`）。

改了配置或代码后要 `./start.sh --restart` 才生效；改了网页文件只需刷新浏览器。

## 2. 五分钟先在仿真里跑一遍

不需要机器人、不需要密钥、不会让任何东西动：

```bash
./start.sh --mock --audio
```

然后打开 http://127.0.0.1:8088 ，顶栏应是绿色的 **MOCK · 仿真**。去「执行监控」看刚跑完那趟：四段导航、三次检查，每条检查有带角度标注的全景、裁切图、判读结果和播报文本。

这一遍跑通说明整条链是好的；之后所有页面操作在仿真里练手，代价为零。

## 3. 接真机

### 3.1 凭据

找管理员在云端界面「API 接入」拿两样东西：**机器人别名**（如 `ntu-dog-00001`，不要用机器人 ID）和 **API 密钥**（`cx_...`，角色 operator、租约模式 auto）。写进 `config/.env`：

```bash
cp config/env.example config/.env      # ⚠️ 已经有 .env 就别再 cp，会把你的密钥覆盖成占位符
```

```bash
CX_HOST=https://certaintyx.sg:8443
CX_ROBOT=ntu-dog-00001
CX_KEY=cx_xxxxxxxx_...
SNAPSHOT_SOURCE=rtsp                   # 真机抓全景
```

密钥只存在服务端，网页里永远显示掩码；`config/.env` 已被 gitignore。

### 3.2 先做只读冒烟（不会让机器人动）

```bash
make smoke
```

它逐项核对：鉴权、别名解析、在线、ROS 可用、急停状态、`/position`、地图与航点、任务语义字段、事件流 SSE、全景 HLS。**有 ❌ 先解决再往下**，对照 [OPERATIONS.md §7 速查表](OPERATIONS.md)。

### 3.3 启动并检查

```bash
./start.sh
```

顶栏变成橙色 **REAL · 真机**，五个状态灯依次是：在线 / 控制权 / 急停 / 定位 / 云端任务。在「总览」点「↻ 刷新状态」，会列出七项**执行前置检查**——七项全绿才能执行任务：

| 检查项 | 不通过时怎么办 |
|--------|---------------|
| 云端网关可达 | 网络问题 |
| 机器人在线 | 确认机器人开机联网 |
| 无急停指令 | 点提示旁的「取消急停」按钮 |
| ROS 可用 | 机器人端 ROS 挂了，读到的都是陈旧值 |
| 定位就绪 | 用下面的「② 启动设备 / ④ 定位」；若提示「定位数据已陈旧 N 小时」说明机器人端不再发布定位话题（仿真/导航栈停了） |
| 云端无进行中的任务 | 点提示旁的「停任务」按钮（详见 [§7 常见问题](#7-常见问题)） |
| 控制权可用 | 现场有人在操作，等对方放手 |

### 3.4 初始化（真机必需，一次性）

「总览 → 机器人初始化」里有三个按钮。**只在真机上按顺序做一次**（机器人不重启、不丢定位就不用重做）：

1. **② 启动设备**——在机器人上拉起导航/定位等模块。不做这步，任务下发会返回成功但机器人不动。
2. **④ 定位**——选地图 + **机器人此刻真实所在（或最接近）的航点**，点定位。服务端最长同步等 20 秒；偏差超 3 米判失败。
3. 顶栏「定位」灯变绿。

> ⚠️ **如果你的机器人别名后面接的是与真狗共用 roscore 的 Gazebo 仿真，绝不要按「启动设备 / 停止设备」**——会把仿真的速度指令接到真狗上、或杀掉真机正在用的节点。那种环境定位是现成的，直接跳到执行。

## 4. 做一次完整巡检

### 4.1 同步地图（每张地图一次；重新建图后要重做）

「地图与导航航点」→ 选地图 → **同步**。画布上会画出航点、邻接边、机器人实时位置。看两个数：航点数对不对、**连通块是否为 1**（大于 1 说明拓扑断裂，跨块的段会「不连通」）。

- 悬停看航点编号与坐标；点一个航点可「添加为任务航点」「设为定位初值」「设为路线起点/终点」。
- 「路线预览」填两个航点算最短路，用来确认拓扑通不通。
- 点云背景是可选的：上传 `.pcd/.ply` 后按体素下采样显示（云端不提供点云下载，得手工上传）。

### 4.2 定义任务航点

「任务航点」页 → **＋ 新建任务航点**，或在地图上点某个导航航点 →「添加为任务航点」（会自动带出 x/y/z/yaw）。

编辑器右半边是**全景角度编辑器**，这是这套系统的核心操作：

1. 点「📷 抓一张作参考图」（或上传一张）——建议先让机器人真的走到那个点再抓，这样看到的就是它到点后的视野。
2. 图上拖动**两条黄线**圈出要检查的方位范围。横轴就是方位角：最左 0°、中间 180°、最右 360°；`from > to`（如 330°→30°）表示跨越左右接缝，系统会自动拼接。
3. 蓝色虚线是**机头方向**（默认 180° = 图像中心）。真机第一次抓图后去「设置 → 机头校准」标定一次：让机器人朝一个已知地标停下，把蓝线拖到该地标所在的列。校准后编辑器里的「相对机头 ±N°」读数才准。
4. 写 **prompt**：必须是能用「是 / 不是」回答的具体问题。好例子：`画面中间的红色消防栓柜门是否关好？`、`地面黄色方格区域内是否有物品堆放？`。
5. 填 **答案模版**：
   - **期望回答**：选「是」或「不是」为通过。例如「门是否关好」期望「是」；「通道是否被占用」期望「不是」。
   - 三句播报：通过 / 不通过 / 无法判断。支持占位符 `{name}`（航点名）、`{answer}`（模型回答）。每句后面有 ▶ 可以试听。
6. 点「试问 VLM（用参考图）」——立刻看到裁切图、模型原始回复、解析出的是/不是、以及**将要播报的那句话**。不满意就改 prompt 或收窄范围，反复试，这一步不动机器人。

### 4.3 建任务

「任务规划」→ **＋ 新建任务**：

- **地图**、**起始点**、**任务航点顺序**（下拉加入，上下箭头排序，也可就地「＋ 新建任务航点」）。
- **起始点**：机器人从哪个导航航点出发。选「自动」= 执行时按机器人当前位置取最近的航点；指定具体航点则每趟都固定从它出发（适合总从充电位/门口起步）。指定后系统仍会核对机器人实际距它多远，超过「容差」（默认 3 m）只在事件里记警告——因为**下发路径的第一个点就是这个起点**，机器人不在附近时第一段会走错。
- **执行选项**（都有默认值，不确定就别动）：

| 选项 | 默认 | 什么时候调 |
|------|------|-----------|
| 速度 / 步态 / 避障 | 机器人默认 | 需要低速或上楼梯时 |
| 到点稳定 (s) | 2 | 机器人到点后还在晃 → 加大，抓图更清晰 |
| 每段超时 (s) | 600 | 按最长一段的实际用时 ×2 |
| 段失败重试次数 | 1 | 避障失败偶发时留 1 |
| 未启动判定 (s) | 25 | 下发后机器人多久没动就认为「没执行」 |
| 掉线判定 (s) | 90 | 云端不可达多久判段失败 |
| 停滞判定 (s) | 180 | 任务在跑但多久没到新航点就认为卡住 |
| 控制权等待 / 重试次数 | 30 / 1 | 现场经常抢控制权时加大 |
| 停任务核实 (s) | 15 | 停任务后最多等多久确认机器人真的停了 |
| 丢定位策略 | 停下并暂停 | 也可选「只记录，继续」或「判段失败」 |
| 结束后返回起点 | 关 | 需要回到起点/充电位时开 |
| 执行前要求定位就绪 | **开** | 真机务必保持开 |
| 停不下来时自动急停 | 关 | 实测机器人偶发不理会停止指令；真机确认过急停行为后再开 |

- 「**路线**」按钮预览各段路径与总长，不连通的段会标红。

### 4.4 执行与看护

点「▶ 执行」：先做一次前置检查（不通过会直接摆出原因和「停掉云端任务并重试」），真机模式还会二次确认。

在「执行监控」里看：

- **分段进度**：每段显示 `已下发 → 导航中（已过 k/n 点）→ 已到达 → 检查中 → 完成`，带下发/到达时刻和幂等键。
- **轨迹**小地图：航点、任务航点（菱形）、当前段路径、机器人位置。
- **检查结果**：带角度标注的全景 + 裁切图 + 模型原始回复 + 判读结论 + 播报文本（可「▶ 重放」）。每条可**人工复核**：判通过 / 判不通过 / 撤销——统计按复核结果算，模型原结论保留下来做评测样本。
- **本次执行的事件**：云端事件（到达/完成/失败/避障/丢定位）与系统事件（下发/抓图/VLM/TTS）合在一条时间线，可导出 CSV。

三个人工干预按钮：

| 按钮 | 行为 |
|------|------|
| ⏸ 暂停 | 当前段走完后停下；点「▶ 继续」接着走 |
| ⏭ 跳过当前航点 | 停掉这一段，从当前位置重新规划下一段 |
| ■ 中止 | 停任务并把本次执行标记为已中止 |

失败或中止之后，执行详情右上角会出现「**↻ 从『某航点』重跑剩余航点**」——新建一次执行，只走没做完的部分。

> ⚠️ **顶栏「⚠ 急停」不是硬件急停**：它让机器人端持续下发停止指令，直到你显式取消；现场遥控仍会与它竞争。实测机器人收到后还会**滑行 5–7 秒**才停住，而且**不会取消云端任务**（取消急停后它会接着走完）。要确保绝对不动，请按机器人上的物理急停按钮。

### 4.5 定时执行

「任务规划 → ⏰ 定时」：**每天固定时刻**（如 `07:30,19:30`，可多个）或**每 N 分钟**。到点时若已有执行在跑会跳过并记事件；执行前照常做前置检查。「立即执行」可以马上试一次。总览会显示「下次定时执行」。

## 5. 接 VLM 与播报

### 5.1 VLM（视觉判读）

「设置 → VLM 视觉判读」，四种提供方：

| provider | 用法 |
|----------|------|
| `mock` | 不调模型，交替回答是/不是。用来把链路跑通、或没有密钥时演示 |
| `qwen` | 阿里通义千问（DashScope 兼容模式）。**地址留空**即用官方地址；模型 `qwen3.5-flash`；密钥填 DashScope 的 `sk-…`（也可用环境变量 `DASHSCOPE_API_KEY`）。非流式调用会自动带 `enable_thinking:false`（少了它 DashScope 直接 400） |
| `openai_compat` | 任何 OpenAI 兼容端点：Ollama（`http://127.0.0.1:11434/v1`）、vLLM、LM Studio、OpenAI |
| `anthropic` | Anthropic 官方 SDK |

接新服务商先在命令行探一次，不动机器人：

```bash
make vlm                                     # 拿最近一次检查的裁切图问一句
make vlm ARGS='--prompt "画面中间是否有一座棕色的圆顶建筑？"'
make vlm ARGS='--provider qwen --model qwen3-vl-plus --key sk-xxx'   # 临时覆盖，不写回配置
```

它打印请求要点、原始回复、解析结果、耗时；失败会带出服务端错误原文（密钥错、模型名错、模型不收图片都能一眼看出）。

两个相关设置：**附整张全景**（除裁切图外再发一张带角度标注的整图，模型能看到「第几度到第几度」，但每次两张图更贵）、**额外请求字段**（JSON 对象，直接合并进请求体，传服务商私有参数，如 `{"vl_high_resolution_images": true}`）。

积累一些人工复核之后，可以评测判读质量：

```bash
make eval          # 用复核结果当标注，重跑当前 VLM，算总体/按航点准确率与误判清单
```

### 5.2 播报（TTS）

- **引擎**：`edge`（微软在线合成，需联网）/ `command`（任意命令行 TTS，模板里用 `{text}`、`{out}`）/ `none`（不合成，只把文本推给浏览器朗读）。合成有超时（默认 20 s），卡住只记错误、不阻断巡检。
- **汇出**（`TTS_SINKS`，逗号分隔，可多选）：
  - `browser`——推到网页播放（页面上要先点一下解除浏览器自动播放限制，顶栏 🔊 亮着）
  - `local`——本机扬声器
  - `http`——**本项目自带的播报服务**，装在机器狗或现场 PC 上（见下）
  - `webhook`——POST 到任意地址

机器狗端播报（零外部依赖，只要 python3 + ffplay）：

```bash
# 把 audio_server 目录拷到有喇叭的机器上
scp -r audio_server user@robot:~/patrol-audio/
ssh user@robot 'cd ~/patrol-audio && python3 -m audio_server --host 0.0.0.0 --port 5566 --token 口令'
```

然后设置里 `TTS_SINKS` 加 `http`、填「播报服务地址」`http://<那台机器>:5566` 和口令。调度系统这边合成好 mp3 直接推过去，**机器人端不需要联网、不需要装任何 TTS**。常驻见 `deploy/patrol-audio.service`。

## 6. 日常维护

| 事情 | 怎么做 |
|------|--------|
| 看系统自检 | 「设置 → 系统自检」：版本、DB 版本、三个后台线程、事件监听、媒体占用、云端请求计数 |
| 看统计 | 「总览 → 近 30 天按航点统计」：检查次数、通过率、平均耗时（按人工复核后的结果算） |
| 查历史事件 | 「任务事件」页：按来源/类型/级别/执行/关键字过滤，可导出 CSV |
| 备份配置 | 「设置 → 备份 / 迁移 → 导出」：任务航点 + 任务 + 定时计划的 JSON |
| 备份数据库 | `make backup`（sqlite 在线备份到 `data/backups`，保留 14 份；WAL 下别直接 cp） |
| 清理媒体 | `make clean-media`（默认先 dry-run 看看；`scripts/cleanup_media.py --keep-days 30 --events` 真删） |
| 重新建图之后 | 「地图」页同步新地图 → 「设置 → 备份/迁移」先导出备份 → 填「旧地图名 → 新地图名」点「重定向」（按 x,y 把任务航点挂到新图最近的导航航点，默认只改 ≤3 m 的，超距的列出来人工处理）→ 每个点重抓参考图、核对角度范围 |
| 收工 | 连续多任务不用停设备。当天结束再按「停止设备」，否则导航模块一直空转耗电 |

日志：`data/logs/app.log`（应用）与 `data/logs/app.out`（stdout）。数据库：`data/scheduler.db`。媒体：`data/media/`（全景/裁切/参考图/TTS 音频）。

## 7. 常见问题

**任务下发返回成功，但机器人不动**
执行记录里会写「任务下发成功但机器人没有动」。按顺序查：是否漏了「② 启动设备」；是否漏了「④ 定位」；急停是否还在下发（顶栏灯）；路径里的航点是否属于另一张地图。

**前置检查：云端有任务在跑：NAVIGATING**
提示里会写清云端任务的地图、航点数、目标：
- **路径为空** → 刚做过「定位」的残留（机器人端重定位期间任务状态就是 NAVIGATING），点提示旁的「停任务」即可。这是最常见的一种。
- **有正常路径且不是你下发的** → 现场有人在操作，等它跑完，别抢。系统不会去停不是它下发的任务。

**前置检查：定位数据已陈旧 N 小时**
机器人端不再发布 `/global_localization`（仿真或导航栈停了）。注意 `/position` 仍会回放缓存值，所以不能靠它判断——重启机器人端的仿真/导航栈，或重新做一次定位。

**中止/停任务点了，机器人还在走**
实测机器人端**偶发不理会**停止指令（云端会回 200）。系统停任务后会核实，核实不了会记一条红色事件「机器人端未响应停止指令」并发通知。此时用顶栏「急停」（注意滑行 5–7 秒、不取消任务），或到现场处理。任务选项里可打开「停不下来时自动急停」。

**我的操作返回 409 / 顶栏显示控制权被别人持有**
同一时刻只有一个人/程序能控制机器人，**现场登录的人可以抢走程序的控制权，反过来不行**。等对方放手，不要靠高频重试去抢。

**抓不到全景，或抓帧很慢**
真机 RTSP 抓一帧实测约 3 秒（等首个关键帧）。抓不到时先在浏览器打开 HLS 地址确认流本身是好的；`8554` 端口被防火墙挡时把「抓图源」改成 `hls`（0.8 秒，但画面落后 2–3 秒）。

**改了 UI 却看不到变化**
现在前端资源带 `no-cache`，普通刷新即可。若是老版本部署，按 Ctrl+Shift+R 硬刷新。

**一切正常但数据不更新**
看「总览 → ROS」。为「不可用」时机器人端 ROS 挂了，接口照常返回但内容是最后一次成功读到的陈旧值。

## 9. 安全须知（真机）

1. **急停不是硬件急停**，也不是锁：它让机器人端持续下发停止指令，现场遥控仍会与之竞争，实测还有 5–7 秒滑行。要确保绝对不动请按物理急停按钮。
2. **停任务 ≠ 停设备**：停任务只让机器人停下，导航等模块还在跑（耗电）；收工才按「停止设备」。
3. **与真狗共用 roscore 的仿真环境里，不要按「启动设备 / 停止设备」**。
4. **定位初值必须是机器人真实所在的航点**：给错了要么偏差超 3 米判失败，要么勉强收敛到错的位置——之后巡检会朝错误方向走，这是有物理风险的。
5. 让机器人动起来之前，确认现场没人在它路径上、有人能按下物理急停。
6. 默认只监听 `127.0.0.1` 且没有登录鉴权。要暴露到局域网，请自己加反向代理和鉴权（见 `deploy/README.md`），并把危险设置从网页上移走。
